# promptgame

한국어 문장으로 한 턴의 행동을 묘사하면, 로컬 LLM이 그 문장을 행동 계획으로 해석하고 게임 코드가 규칙대로 비용·명중·피해를 판정하는 턴제 전투 시제품이다. 10×8 고정 전장에서 용병 하나가 고블린·오크와 싸운다.

- AI(Ollama 로컬 모델)는 문장을 최대 3단계의 계획 JSON으로 바꾸기만 한다. 실행 가능 여부·AP·명중·피해·상태 변화는 전부 코드가 정한다.
- 외부 API는 쓰지 않는다.

## 설치

필요한 것: Windows 11(확인 환경), Python 3.12, [uv](https://docs.astral.sh/uv/), [Ollama](https://ollama.com/).

```bash
uv sync
ollama pull gemma4:12b-it-qat
```

## 실행

```bash
uv run promptgame
```

창(1280×800)이 뜨면 아래 입력창에 문장을 적고 Enter를 누른다. 종료는 창 닫기. 종료할 때 콘솔에 턴 기록 파일 경로가 나온다. Ollama가 꺼져 있어도 창은 뜨며, 해석할 때 실패 사유와 폴백 명령을 안내한다. F3 또는 환경변수 `PROMPTGAME_DEBUG=1`은 개발용 격자·좌표를 켠다(기본 꺼짐).

## 설정 (환경변수)

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `PROMPTGAME_MODEL` | `gemma4:12b-it-qat` | 해석 모델 |
| `PROMPTGAME_OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama 주소. Windows에서 `localhost`는 요청마다 지연이 생길 수 있어 127.0.0.1을 쓴다 |
| `PROMPTGAME_TIMEOUT` | `15` | 해석 응답 시간 제한(초) |
| `PROMPTGAME_LOG_DIR` | `logs` | 턴 기록(JSON Lines) 폴더 |
| `PROMPTGAME_SEED` | 없음(무작위) | 주사위 시드. 주면 매 판 같은 시드로 시작 |
| `PROMPTGAME_DEBUG` | 없음 | `1`이면 개발용 격자·좌표 표시 |

## 조작

- 한 문장 = 한 턴. 행동 포인트(AP) 4 안에서 최대 3단계.
- 문장 예: `남쪽으로 두 칸 가` · `신속하게 다가가서 녀석의 머리를 벤다` · `화염구로 오크를 태워` · `물약 마시고 뒤로 물러나` · `오크 다리를 노려 단검을 던지고 방어 자세를 잡아` · `돌려베기`
- 수락된 계획은 먼저 아래 띠에 단계별 AP·명중률로, 전장에는 경로 점선·도착 고리·대상 표식으로 표시되고, 약 1초 뒤 자동으로 실행된다(확인 키 없음). 실행 결과는 이동·베기·화염구·피격 같은 연출로 순서대로 보이고, 같은 순서로 아래 띠에 결과 문장이 나온다. 연출 중에는 새 문장을 받지 않는다. 전체 기록은 `logs/`의 파일에 남는다. 비용 초과나 지형·사거리·시야 때문에 안 되는 계획은 **전체가 거부**되고 턴·상태는 그대로다.
- 대상을 정할 수 없으면(예: 옆에 두 적이 있는데 "녀석") 후보를 보여 주고 다시 묻는다.
- `다시 시작`: 새 판(AI 없이 즉시 처리). 승패가 난 뒤에는 이 명령만 받는다.
- Esc: 입력 지우기. AI가 해석하는 동안 들어온 새 문장은 실행하지 않는다.
- AI를 쓸 수 없을 때(서버 실패, 형식 오류 2회)는 문장 전체가 `대기` `방어` `공격` `물약` `북` `남` `동` `서`와 정확히 같을 때만 처리한다. `공격`은 옆에 적이 하나일 때만 된다.

규칙 수치(능력치, 동작 비용, 수식, 판정 공식, 적 대응)는 `src/promptgame/domain/level.py` 한 곳에 있다.

## 화면과 자산

전장은 관문 앞 배경 그림 하나 위에 캐릭터를 원근 투영해 그린다. 내부 좌표는 10×8 칸이지만 화면에 격자선은 없고, 계획 표시 단계에만 경로·대상 표식이 나온다. 판정은 domain이 먼저 끝내고, 화면은 그 결과 이벤트를 순서대로 연출한다(난수·피해 재적용 없음).

`assets/`의 그림은 `tools/build_assets.py`가 Vault의 시안 두 장(`tollgate-spatial-backdrop.png`, `mockup-06-spatial-battle.png`, 내장 이미지 생성 도구로 만든 자체 제작 그림)에서 잘라 만든 **임시 자산**이다. 캐릭터 컷아웃은 손으로 찍은 윤곽으로 잘라 가장자리에 배경 조각이 남고, 배경의 오른쪽 아래 웅덩이는 판정 지도에 없어 판석으로 덮었다. 완성 자산 사양은 Vault의 `promptgame 시각 자료` §4에 있다. 글꼴 Noto Sans KR·Noto Serif KR은 SIL Open Font License 1.1이며 `assets/fonts/OFL.txt`를 동봉한다. 자산이 없으면 대체 도형으로 실행된다.

## 구조

```text
src/promptgame/
  domain/          전장·수치, 상태·시야·경로, 계획 구조, 대상 확정, 계획 검증, 실행·판정·적 턴, 결과 문장
  application/     LLM·기록 인터페이스, 응답 형식 검증, 지시문·상태 요약, 해석·재시도·폴백, 세션(턴 진행·스레드·연출 단계)
  infrastructure/  설정, Ollama HTTP 클라이언트, JSON Lines 기록
  presentation/    pygame 창·이벤트 루프, 좌표 투영(camera), 자산 적재, 표시 상태, 연출 큐(animation), 그리기, 한글 입력
  main.py          구성 요소 생성과 연결
assets/            배경·캐릭터 컷아웃·초상화·지형 조각·글꼴
tools/             해석 측정 도구와 문장 30개, 자산 가공(build_assets.py), 화면 캡처(capture_frames.py)
docs/eval/         측정 결과 파일
```

코드 의존 방향은 presentation → application → domain, infrastructure → application(ports)·domain이다. domain은 pygame·HTTP·파일을 쓰지 않는다.

## 검증

### 자동 테스트 (LLM 없음)

```bash
uv run pytest
```

- 규칙: 설계 예시 E1~E6의 고정 시드 재현, 동작 8종·수식별 비용·명중·피해·상태, 거부된 계획 뒤 상태·난수 불변, 실행 중 후속 단계 취소, 적 턴, 대본 승리·패배, 같은 시드 재현.
- 해석·연결: 가짜 LLM 클라이언트와 로컬 테스트 HTTP 서버로 형식 검증·재시도 1회·서버 실패 종류·폴백 정확 일치·되묻기·중복 입력 차단.
- 화면: SDL 이벤트 순서 재현(조합·삭제·제출), 창 없는 그리기(`SDL_VIDEODRIVER=dummy`), 격자선 없음, 자산 없을 때 대체 도형, 연출 중 재시작.
- 연출: 설계 예시 E1·E2·E6의 이벤트가 기대 순서의 연출 단계로 바뀌고, 재생 뒤 표시 상태가 실제 상태와 같으며, 연출이 난수를 쓰지 않는다.

```bash
uv run python tools/capture_frames.py --scenario e1 --out docs/frames
```

실제 코드로 한 턴(정해진 계획)을 창 없이 돌리며 프레임을 저장한다. 시나리오 `e1`·`e2`·`e6`·`walk`.

### 실제 LLM 측정

```bash
uv run python tools/eval_interpreter.py
```

모델을 미리 적재한 뒤 문장 30개(단일 동작 10 · 방법 수식·순서 복합 10 · 대상 지정·모호·무관 10)를 1회씩 해석해, 정규화한 계획이 기대 계획 후보 중 하나와 같으면 정답으로 센다. 결과는 `docs/eval/`에 저장된다. 정확도·응답 시간의 목표치는 없다.

2026-10-06 03:26 측정(`docs/eval/eval-gemma4_12b-it-qat-20261006-032703.json`, RTX 5060 Ti 16 GB, Ollama 0.30.7): 정답 29/30, 응답 중앙값 1878 ms, 95퍼센타일 3221 ms, 재시도 0, 실패 0. 틀린 1건은 "방금 때린 녀석을 다시 벤다"를 오크 공격 두 단계로 해석한 것이다. 30개 중 6개는 지시문 예시에 같은 문장이 들어 있는 설계 예시 문장이다. 이 수치는 이 문장 묶음과 환경에서의 1회 측정이다.

### 수동 확인

실제 Windows 창에서 한글 조합 중 글자 밑줄 표시, 조합 중 Backspace, Enter 제출, 계획·결과 줄 표시, 그래픽·연출, 승패·다시 시작·종료를 눈으로 확인한다. 자동 테스트는 SDL 이벤트 순서를 재현할 뿐 실제 IME 동작을 보장하지 않는다.

## 턴 기록

`logs/turns-*.jsonl`에 판 시작(시드·모델)과 매 턴의 문장, 해석 출처(`llm` / `fallback` / `none`), 실패 종류, 시도 횟수, 응답 시간, AI에 보낸 상태 요약, 응답 원문, 계획 JSON, 검증 결과와 비용, 단계별 주사위·결과, 적 턴 결과, 턴 전후 상태가 한 줄씩 남는다. 같은 초기 상태·같은 확정 계획 순서·같은 시드면 판정 결과가 같다. 같은 문장을 다시 LLM에 보내 항상 같은 계획을 받는다는 보장은 아니다.
